# Code review and correction record — 2026-10-11

Reviewed the complete saved application: 30 development objects plus package
metadata. This comprises eight application tables, two draft tables, six CDS
views, six access roles, two behavior definitions, two metadata extensions,
three classes, and one service definition. Also reviewed the seed fixture,
readable source copies, metadata generator, packaging checks, and setup notes.
Installer recovery archives and SAP reference samples are not application code.

The review is of the local serialized repository and the SAP diagnostics supplied
in the conversation. It is not a fresh export of the current SAP server. Any
additional Eclipse changes must be reconciled during abapGit's import review.
The pre-review source is preserved in backups/pre-audit-20261011.zip.

## Findings corrected

| Finding | Correction |
| --- | --- |
| Editable amounts/quantities referenced static read-only currency/unit fields in the original batch. The last patch used always-read-only dynamic controls. | Item price, quantity, currency, and unit now use ordinary editable fields. Only missing codes are defaulted. Backend validations require EGP/EA; unsupported values can be corrected in the draft. Header currency stays read-only with the read-only header amount. |
| Mandatory annotations and value-help validation were being relied on without backend save checks. | Added header/item validations, including supplier/product existence scoped to the current user, required references and date, positive quantities/prices, and currency/unit restrictions. The reference selects are batched and guarded against empty FOR ALL ENTRIES inputs. |
| A consumer could create duplicate item numbers under one PO. | Validation reads siblings from RAP's transaction buffer and checks item-number uniqueness per PO and active/draft version. It sees unsaved changes. Different orders may reuse item numbers. |
| The recent create default overwrote a nonempty currency, potentially relabelling an amount. | Defaults fill missing values only. Invalid supplied values fail validation instead of being silently replaced. |
| Invalid dates and values too large for the future line amount were unchecked. | Checks calendar validity using ABAP timestamp conversion and checks the multiplication in DECFLOAT34 before storage in CURR(15,2). Header summation/rounding will be implemented with the amount calculation milestone. |
| Some read failures/messages were dropped; defaults replaced earlier messages. | Feature/authorization/validation reads propagate FAILED/REPORTED. Default determinations preserve earlier reported messages and skip already-defaulted records. |
| Empty status could enable operations in feature control. | Only status N enables PO/item modifications. Creator checks and the current released-order restriction remain enforced. |
| Draft activation had no business validations assigned to Prepare. | Header and item validations are included with always, with state-message invalidation and draft-aware parent paths for item errors. |
| Zero totals were exposed even though calculation is not implemented. | Removed TotalAmount/NetAmount from the current UI projections and metadata extensions. Their persistence and interface fields remain for milestone 4. They are not returned as calculated service values. |
| Order reference was annotated as a semantic key without a uniqueness rule. | Removed that annotation. The UUID remains the technical identity; the reference remains the visible title. |
| Product help included unsupported units. | Limited the product selection CDS to EA; backend reference validation uses the same constraint. |
| Seed reruns equated an existing header with a complete fixture and could reuse an incompatible product unit. | Reruns verify the named linked document chain and its owner/reference consistency. New loads stop on conflicting product units. Existing rows are never overwritten or repaired automatically. |
| Local checks did not detect the original cross-file amount/currency inconsistency. | Added a check spanning CDS semantics and BDEF controls, schema checks for all ten tables, five regression tests for that checker, and a pinned independent ABAP/CDS parser. |
| Metadata regeneration could overwrite settings later exported from SAP. | Generator now refuses existing metadata unless --overwrite-prepared is explicitly supplied. This switch is for unactivated template metadata only. |

The previous provider-contract, SOURCE/TARGET, and secondary ID-key corrections
remain in the reviewed source. No application/draft table schema is changed in
this revision. The original SAP export ZIP remains byte-for-byte intact.

## Verification evidence and limits

- abaplint 2.120.73: configured ABAP/CDS parser, XML consistency, duplicate-method,
  empty-statement, and obsolete-statement checks pass across 56 repository files.
  This is a grammar/static check, not SAP activation or full RAP semantic analysis.

  checks and verifies the original SAP ZIP checksum. Intentional baseline edits
  are limited to the seed source and repository README.
- tools/test_package_checks.py: five tests pass, including a mutation that
  reintroduces the original static currency/unit error and is rejected.
- Added 13 ABAP Unit methods in ZBP_I_P2P_PO_MF001. They cover valid and invalid
  headers/items, foreign-reference lookup results, calendar dates, zero/negative
  values, unsupported codes, amount limits, duplicate lines, and separation of
  active/draft versions and different POs. These tests have NOT run in SAP.
  They test pure rules; they do not prove authorization, SQL scoping, or RAP wiring.

  such as CL_ABAP_BEHAVIOR_HANDLER and IF_OO_ADT_CLASSRUN. We have not fabricated
  SAP stubs or represented that attempt as a passing semantic check.
- SAP activation, released-API/ATC checks, ABAP Unit execution, draft integration,
  OData authorization, and Fiori runtime tests remain pending.

## Known remaining work

1. The reported Inverted Individual primary-key warning is unresolved in the
   server's technical settings. The table definitions activated with a warning.
   Inspect/fix the affected table settings in ADT and export SAP's resulting
   metadata. No guessed database-index XML is included in this revision.
2. Totals and ReleaseOrder are still milestone 4. An empty pending PO can be
   saved; requiring at least one item is a release rule. Unfinished drafts may
   be stored, while activation of invalid header/item content is rejected.
3. Receipt/invoice behavior, matching, supplier locking, rejection/payment
   actions, the overview, and the saved Fiori app have not been implemented.
4. Before adding receipts under released orders, separate owner authorization
   from the current unreleased-only edit permission and freeze PO commercial
   fields while allowing the document chain to enter draft.
5. The seed loader is a one-at-a-time console bootstrap. It is not a concurrent
   production seeding API. Owner isolation protects RAP/OData consumers; developer
   direct-SQL privileges are outside that application boundary.
6. UI messages are English text for the agreed demonstration. A multilingual
   version should use translatable T100 messages.
